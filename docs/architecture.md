# Microloop Architecture

Microloop is a **verified local Decision JIT for AI agents**. It intercepts repetitive, bounded agent decisions and serves them locally in under 0.5 milliseconds with mathematical safety guarantees, falling back seamlessly to cloud LLMs whenever novelty, ambiguity, or policy drift occurs.

```text
               +--------------------------------------+
               |      Agent Orchestration Loop        |
               | (browser-use, LangGraph, custom agent)|
               +-------------------+------------------+
                                   |
                       Input State | {task, context}
                                   v
             +---------------------------------------------+
             |             Microloop Decision Site         |
             +---------------------+-----------------------+
                                   |
                   Is Active Path  |
                   Verified Local? |
                         /         \
                  YES   /           \   NO (or Abstain /
          (< 0.5 ms)   /             \      Shadow Eval)
                      v               v
            +------------------+     +-------------------+
            | Local Fast-Path  |     | Original Fallback |
            |  Engine (Exact / |     |    Remote LLM     |
            |   Sparse TF-IDF) |     |  (120 - 250 ms)   |
            +---------+--------+     +---------+---------+
                      |                        |
                      |    Selected Action     |
                      +------------+-----------+
                                   |
                                   v
                      +-------------------------+
                      |   Environment Action    |
                      |  Execution (DOM / API)  |
                      +------------+------------+
                                   |
                            Outcome Receipt (quality=1.0/0.0)
                                   v
                      +-------------------------+
                      | Independent Verifier &  |
                      | Drift Demotion Monitor  |
                      +-------------------------+
```

## 1. Core Philosophy: Prediction != Authority

In conventional software, a JIT compiler (such as V8 or PyPy) observes interpreted execution, identifies hot paths, compiles machine code, and de-optimizes back to the interpreter if dynamic type guards fail.

Microloop brings this principle to probabilistic AI agents:
1. **Prediction:** A hypothesis generated by an embedded local model or table (Exact match, Sparse TF-IDF, or ModernBERT). A prediction alone has **zero serving authority**.
2. **Authority:** An operational permission granted strictly through empirical verification on holdout tasks and shadow executions using Hoeffding concentration bounds.
3. **Continuous De-optimization:** Active fast paths continuously run a small fraction of comparison traffic against the original LLM fallback. If business rules drift, Microloop automatically de-optimizes (demotes) to shadow within 1–4 decisions.

## 2. Decision JIT Lifecycle

Every decision artifact transitions through a strict formal state machine:

```text
  [ OBSERVE ] ──(State Repeat >= 50% & Positive ROI)──▶ [ CANDIDATE ]
                                                              │
                                                      Compile Local Path
                                                              │
                                                              ▼
  [ ACTIVE ] ◀──(Hoeffding Holdout Bound >= Policy)─── [ SHADOW ]
      │                                                       ▲
      │                                                       │
      └────── Policy Drift Detected / Accuracy Drop ──────────┘
             (Autonomous Demotion in 1 - 4 Decisions)
```

1. **`OBSERVE`**: The agent executes remote LLM fallbacks. Decisions, states, and execution outcomes are recorded in local SQLite storage.
2. **`CANDIDATE`**: When observation history accumulates sufficient verified outcomes, `client.compile()` fits candidate local parameters.
3. **`SHADOW`**: The artifact is calibrated with negative margins and evaluated on live traffic in shadow mode. The original fallback still controls execution.
4. **`VERIFIED` / `ACTIVE`**: When holdout evidence satisfies the site's required quality threshold under one-sided Hoeffding bounds, the artifact is atomically promoted to `ACTIVE`.
5. **`DEMOTION`**: Comparison traffic continuously checks agreement with the teacher. If mismatch occurs, the artifact is immediately demoted to `SHADOW`.

## 3. Request-Level Dispatch Flow

```text
  State In ──▶ Validate Schema ──▶ Check Exact Coverage ──▶ Check Calibration
                                                                   │
    ┌───────────────────────── Fast Path ──────────────────────────┘
    │ (Verified & Active)
    ▼
  Persist Decision (WAL) ──▶ Return Choice (<0.5ms) ──▶ Execute Host Action
    │ (Fail-open fallback)                                      │
    ▼                                                           ▼
  Abstain / LLM Fallback ◀──────── Demote if Drifting ◀─── Record Outcome
```

Every incoming request adheres to these operational guarantees:
- **Schema Validation:** Strict type checking (`string`, `integer`, `number`, `boolean`, and nullable variants `?`).
- **Fail-Open Safety:** Any engine exception, database lock timeout, or uncalibrated state immediately routes to the fallback callable. Applications never crash due to internal JIT errors.
- **Write-Before-Return:** Verified fast-path decisions are persisted to the SQLite WAL before returning. If persistence fails, the fallback is invoked.

## 4. Subsystem Components

```text
+------------------------------------------------------------------------+
|                          Microloop Client API                          |
|                       (python/microloop/microloop)                     |
+-------------------+--------------------+-------------------------------+
|  Site Profiler    | Discovery Engine   | Decision Runtime Orchestrator |
|  (profiler.py)    | (discovery.py)     | (decision_api.py)             |
+-------------------+--------------------+-------------------------------+
|                      Local Execution Engines                           |
|  - Exact Hash Table (exact_engine.py)                                  |
|  - Sparse TF-IDF Semantic Coverage Engine (semantic_coverage.py)       |
|  - Microloop Decision Model v1 (internal/model/)                       |
+------------------------------------------------------------------------+
|                      Local Embedded Storage Layer                      |
|  - SQLite WAL (decision_store.py, schema v4, CHECK constraints)        |
+------------------------------------------------------------------------+
```

### 4.1 Orchestration Layer (`decision_api.py`)
- Exposes `Microloop`, `decision()`, and `record_outcome()`.
- Thread-safe dispatch with asynchronous support (`decide_async()`).
- Atomic transactions for promotion, demotion, and zero-downtime hot swapping.

### 4.2 Economic Profiler (`internal/profiler.py`)
- Analyzes local decision history before spending resources on shadow qualification.
- Computes exact repeat rate, choice entropy (Shannon bits), verifier completeness, and policy volatility.
- Returns advisory recommendations: `strong_candidate`, `needs_more_data`, `poor_repetition`, `weak_verifier`, `high_volatility`, and `low_economic_value`.
- **Isolation:** The profiler is strictly advisory and cannot grant serving authority.

### 4.3 Discovery Engine (`discovery.py`)
- Ingests raw JSON/JSONL execution logs from multi-agent frameworks (browser-use, LangGraph, OpenAI, Anthropic).
- Clusters model calls by call site, measuring input repetition and output entropy.
- Ranks candidate sites by net annual dollar savings.

### 4.4 Semantic Coverage Engine (`internal/semantic_coverage.py`)
- Sparse character n-gram TF-IDF representations.
- Sub-millisecond vectorization (0.012 ms, 0.5 MB memory footprint).
- Negative-margin decision boundaries with counterexample contraction.
- Ambiguity abstention whenever decision regions overlap.

### 4.5 Microloop Decision Model v1 (`internal/model/`)
- Internally packaged, fine-tuned ModernBERT decision model.
- Calibrated bounded choice heads with temperature scaling.
- Runs natively on Apple Silicon (MLX) and Linux x86_64 (CPU).

### 4.6 Persistence Engine (`internal/decision_store.py`)
- Zero-daemon SQLite storage with Write-Ahead Logging (`PRAGMA journal_mode=WAL`).
- Strict schema version 4 with CHECK constraints and foreign keys.
- Measured sustained write throughput: **5,107 writes/sec** under concurrent loads.

## 5. Zero-Daemon, Zero-External Infrastructure

Microloop requires:
- **NO** external vector database (Pinecone, Qdrant, Milvus, Chroma).
- **NO** distributed caching layer (Redis, Memcached).
- **NO** task broker (Kafka, Celery, RabbitMQ).
- **NO** background daemon process.

Everything runs in-process inside your application runtime, with state stored in `.microloop/decisions.db`.
