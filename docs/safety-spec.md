# MICROLOOP FORMAL SAFETY SPECIFICATION & INVARIANT SPEC v1.0

**Document:** Formal Verification & Safety Specification  
**System:** Microloop Decision JIT  
**Version:** 1.0.0  
**Scope:** Machine-adjacent runtime guarantees, transition invariants, and mathematical verification bounds.

---

## 1. System Model & Core Philosophy

Microloop is a verified local Decision JIT. It intercepts repetitive agent decisions and serves verified fast paths with sub-millisecond latency while maintaining the safety profile of the slow teacher.

### The Fundamental Separation: Prediction $\ne$ Authority
- **Prediction:** An unverified choice hypothesis generated by a local statistical or neural mechanism (such as `ExactEngine`, `SparseTFIDF`, or `DecisionModelEngine`). A prediction has zero serving authority on its own.
- **Authority:** An immutable operational right granted strictly by the empirical lifecycle when a statistical candidate proves non-inferiority against a verified ground-truth teacher under holdout and shadow evaluations.

```
                    ┌────────────────────────────────────────────────────────┐
                    │                   MICROLOOP LIFECYCLE                   │
                    │                                                        │
                    │     [OBSERVE] ──compile──> [CANDIDATE] ──calibrate──>  │
                    │                                                        │
                    │     [SHADOW] <──demote── [ACTIVE] <──evaluate/swap───  │
                    │        │                    ▲                          │
                    │        └──requalify(fresh)──┘                          │
                    └────────────────────────────────────────────────────────┘
```

## 2. State Transition Model

Every decision artifact for a given DecisionSite $S$ resides in exactly one state $s \in \mathcal{S}$:
$$\mathcal{S} = \{\text{OBSERVE}, \text{CANDIDATE}, \text{SHADOW}, \text{VERIFIED}, \text{ACTIVE}, \text{RETIRED}\}$$

### State Transition Table
| Source State | Target State | Triggering Operation | Required Preconditions | Postconditions & Side Effects |
|---|---|---|---|---|
| **OBSERVE** | **CANDIDATE** | `client.compile(S)` | $N_{\text{fallback}} \ge N_{\text{min\_samples}}$, split history valid | Uncalibrated artifact payload inserted; initial partitions created. |
| **CANDIDATE** | **SHADOW** | `compile` completion | Valid candidate payload | Status updated to `SHADOW`; ready for calibration. |
| **SHADOW** | **SHADOW** (Calibrated) | `client.calibrate(S)` | Uncalibrated shadow artifact; valid verifier | Regions calibrated; profile attached; immutable profile digest committed. |
| **SHADOW** | **VERIFIED** | `client.evaluate(S)` | Fresh shadow outcomes $\ge N_{\text{min}}$, all safety bounds passed | Verified record logged; ready for activation or hot-swap. |
| **VERIFIED** | **ACTIVE** | `client.evaluate(S)` or `client.hot_swap(S)` | Qualified evaluation record exists | Epoch assigned; becomes primary fast-path serving authority. |
| **ACTIVE** | **SHADOW** | `client.reevaluate(S)` | Drift detected ($\Delta_{\text{lower}} < -\delta_{\text{max}}$ or $Q_{\text{lower}} < q_{\text{min}}$) | Demoted atomically; fast paths halted; all traffic falls back to teacher. |
| **SHADOW** | **ACTIVE** | `client.maintenance()` | Fresh post-demotion outcomes pass `evaluate` bounds | Requalified atomically; serving authority restored. |
| **ACTIVE** | **RETIRED** | `compile(replace=True)` or `hot_swap` | Replacement candidate promoted | Lineage link recorded; serving authority permanently revoked. |
| **VERIFIED** | **RETIRED** | Replacement compile | Superseded before activation | Lineage recorded; cannot be served. |

### Forbidden Transitions (Fail Closed)
The runtime strictly forbids and rejects:
1. $\text{OBSERVE} \to \text{ACTIVE}$ (Immediate activation without calibration and evaluation).
2. $\text{CANDIDATE} \to \text{ACTIVE}$ (Activation without shadow testing).
3. $\text{SHADOW} \to \text{ACTIVE}$ without qualification evidence passing all bounds.
4. $\text{RETIRED} \to \text{ACTIVE}$ (A retired artifact cannot be reactivated; a new candidate must be compiled).
5. Multiple concurrent $\text{ACTIVE}$ artifacts for the same site version.

## 3. Formal Invariants

### Invariant 1: Authority Invariant
A decision result $d$ may have $\text{source} = \text{fast\_path}$ if and only if there exists a valid artifact $A$ such that:
$$A.\text{status} = \text{ACTIVE} \quad \land \quad A.\text{site} = S.\text{version} \quad \land \quad A.\text{epoch} \le d.\text{created}$$
If no such artifact exists, the runtime must set $\text{source} = \text{fallback}$.

### Invariant 2: Fallback Invariant
For any input state $s$, if $s$ falls outside qualified coverage, has insufficient confidence, matches ambiguous conflicting regions, or encounters store/engine faults:
$$\text{decide}(S, s) \implies \text{source} = \text{fallback} \quad \land \quad \text{choice} = \text{fallback\_result}.\text{choice}$$
No engine exception, parse failure, or numerical singularity may raise an uncaught exception to the caller.

### Invariant 3: Single-Active Invariant
For any DecisionSite version $S$:
$$|\{A \in \text{Artifacts}(S) : A.\text{status} = \text{ACTIVE}\}| \le 1$$
Enforced at the database level via a partial unique index:
```sql
CREATE UNIQUE INDEX one_candidate ON artifacts(site)
WHERE status IN ('CANDIDATE','SHADOW','VERIFIED','ACTIVE');
```

### Invariant 4: Freshness Invariant
When an artifact is demoted from `ACTIVE` to `SHADOW` at timestamp $t_{\text{demote}}$, only outcomes recorded strictly after the demotion epoch can satisfy requalification:
$$\text{Evidence}(A_{\text{requalify}}) \subseteq \{r \in \text{History}(S) : r.\text{created} > A.\text{epoch} \land r.\text{source} = \text{fallback}\}$$
Stale outcomes recorded prior to demotion cannot prevent or satisfy requalification.

### Invariant 5: Monotonic Non-Expansion Invariant
For any active semantic region $R$ with radius $r(t)$ at time $t$:
$$r(t_2) \le r(t_1) \quad \forall t_2 > t_1$$
An active region's radius can only contract (tighten) upon receiving counterexamples. A region cannot expand its serving volume without compiling a fresh candidate and completing full shadow qualification.

### Invariant 6: Counterexample Contraction Invariant
Upon receiving a verified decision outcome $(s, c^*)$ where $c^* \ne R.\text{choice}$:
$$s \in \text{Cover}(R) \implies r_{\text{new}} \le \| \vec{s} - \vec{\mu}_R \| - \epsilon$$
The boundary is immediately tightened so that $s$ falls outside $R$'s serving radius, or negative margin is increased.

### Invariant 7: Artifact Cryptographic Integrity Invariant
Every artifact payload is cryptographically hashed:
$$\text{checksum} = \text{SHA256}(\text{canonical}(A.\text{payload}))$$
$$\text{profile\_id} = \text{SHA256}(\text{canonical}(A.\text{profile} \setminus \{\text{"id"}\}))$$
If either digest does not match its recorded hash, the runtime must raise an integrity violation and refuse all fast-path serving authority.

### Invariant 8: Verifier Identity Invariant
During evaluation or reevaluation, the verifier identity and version $(V_{\text{id}}, V_{\text{ver}})$ must exactly match the verifier used during calibration:
$$(V_{\text{id}}, V_{\text{ver}})_{\text{eval}} = (V_{\text{id}}, V_{\text{ver}})_{\text{calib}}$$
Any verifier mismatch immediately invalidates the evaluation candidate.

### Invariant 9: Transactional Atomicity Invariant
All state-modifying operations (`compile`, `calibrate`, `evaluate`, `promote`, `demote`, `hot_swap`, `compact`) must execute within an exclusive SQLite transaction. If a crash or error occurs, the transaction rolls back cleanly with zero partial state.

### Invariant 10: Retention Auditability Invariant
Compaction and pruning operations may delete historical raw decision rows, but must never delete:
- The active evaluation window evidence.
- Partition IDs defining current active/shadow artifacts.
- Historical `events`, `promotion_records`, `drift_checks`, and `state_coverage` summaries.

## 4. Failure Mode Matrix & Fail-Closed Semantics

| Failure Condition | Failure Response | Invariant Preserved |
|---|---|---|
| **Corrupted Vector / Radius** | Reject match $\to$ `outside_coverage` $\to$ Fallback | Invariant 1 & 2 |
| **Abrupt Crash During Swap** | SQLite WAL rolls back uncommitted transaction | Invariant 3 & 9 |
| **Verifier Throws Exception** | Abort evaluation; candidate remains in SHADOW | Invariant 1 & 9 |
| **Database File Read-Only** | Fast path / fallback served; write error absorbed | Invariant 2 |
| **Outcomes Unavailable** | Holdout comparison rate escalates; decay halted | Invariant 1 & 4 |
| **Drift Detected** | Atomic demotion to SHADOW within 50 decisions | Invariant 1 & 4 |
